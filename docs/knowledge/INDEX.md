# Team knowledge index

The shared source of truth for things the code and git history don't tell you:
decisions and why they were made, gotchas, rejected approaches and team conventions.

- Updated through `/team-knowledge:share-context` and reviewed in PRs. Don't edit it as a changelog; keep each topic current.
- One line per topic. Claude reads this file first, then opens only the topics it needs.

| Topic | File | What's in it |
|---|---|---|
| Architecture | [architecture.md](architecture.md) | How the system fits together and the major design decisions |
| Conventions | [conventions.md](conventions.md) | Coding, naming, testing and review conventions the team follows |
| Deployment | [deployment.md](deployment.md) | Environments, release process, config and infrastructure notes |
| Gotchas | [gotchas.md](gotchas.md) | Non-obvious traps that don't belong to a single topic |
